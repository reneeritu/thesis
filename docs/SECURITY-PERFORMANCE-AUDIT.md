## How the site works

### Auth

`POST /auth/register` creates a `ChainNode`: bcrypt password (12 rounds), a 12-word BIP-39 seed shown once, an AES-encrypted copy of the seed, and a SHA-256 hash of the normalised seed. The response includes a JWT (`alias`, `nodeId`, `tokenVersion`, default 7 days) and the seed phrase. `POST /auth/login` and `POST /auth/recover` issue a new JWT. Recover compares the SHA-256 of the submitted phrase to `seedHash` and bumps `tokenVersion`, which revokes older tokens.

`POST /auth/recover/trustees` currently lets anyone who knows an alias store a new password hash and ask trustees to approve it. On majority, that hash replaces the real password. There is no UI for voting. Per owner decision, those routes are removed until a real UI exists.

The frontend stores the JWT in `sessionStorage` (`frontend/src/lib/session.ts`). That moves to an httpOnly cookie (see [Session cookie](#session-cookie-httponly)).

### Profiles

`GET /nodes/:alias` is public. If the profile owner has blocked the viewer, the profile routes refuse. `PATCH /nodes/me` allow-lists interests, tools, mediums, portfolio URL, keywords, statement, and links. It does not accept reputation, status, or password fields.

### Spaces

A space has members, admins, `privacyDefault` (`public` / `process_visible` browse fully; otherwise a public summary), and join mode (`open` / `invite_only` / `application`). Invite codes are 16 hex characters (`crypto.randomBytes(8)`), generated by admins, default single-use, 15-day expiry.

### Projects and traces

Visibility is `fully_public`, `process_visible`, or `space_only`. List routes that call `assertFullProcessLogReadable` or `getProjectPayloadForViewer` in `src/utils/projectAccess.ts` honour that. Several by-id routes do not. Those are the IDOR findings below.

### Uploads

Multer writes files under `UPLOAD_DIR`. `GET /media/:id` serves bytes. Certificate artwork (`POST /upload/cert-artwork` and generated SVG on `PUT /nfts/:id/artwork`) goes through `src/services/svgSanitise.ts`. General `POST /upload` and `POST /upload/archive-evidence` do not.

### Messages, governance, everything else

DM and space-message routes check that the caller is a participant or member. Notification read routes check `recipientAlias`. Governance proposal detail is public on purpose. Mediations, archives, credits, references, endorsements, forks, and `GET /traces/:id` do not apply the same visibility rules.

### UI

`frontend/src/App.tsx` lazy-loads most pages, then always mounts atmosphere, a custom cursor, and a dot field. The hub reputation view is `CrystalRadar3D` (React Three Fiber). The live homepage is `frontend/src/pages/Landing.tsx`, not `LandingLayout` (that file is only `/legacy-landing`).

## Alias, emoji, and duplicate names

Already enforced on register:

- `src/schemas/auth.ts` `registerSchema`: `^[a-z0-9_-]+$`, length 3–30 (`aliasMinLength` / `aliasMaxLength` in `src/config/defaults.ts`).
- `frontend/src/pages/RegisterPage.tsx` trims, lowercases, and uses the same regex before the request.
- `src/models/Node.ts` stores `alias` with `unique: true`, `lowercase: true`, `trim: true`.
- `src/routes/auth.ts` returns 409 `Alias already taken` when `findOne({ alias })` hits.

A second account cannot take the same name. Emoji, spaces, uppercase, and other Unicode (including zero-width characters) are rejected on register.

Gaps to fix:

- Login (`frontend/src/pages/LoginPage.tsx` and `loginSchema`) only trims. `Alice` does not match stored `alice`, so a real user looks locked out.
- No reserved names (`admin`, `system`, `support`, `etch`, `null`, `undefined`).
- ASCII lookalikes stay allowed (`adm1n`, `admin_`). That is acceptable. Do not add a homoglyph library.
- Two parallel registers can both pass `findOne`. The unique index then throws Mongo `11000`, which `src/middleware/errorHandler.ts` turns into a generic 500. `addBlock` may already have written an identity block for the loser.

## Critical

### `src/routes/admin.ts` — open migration

`POST /api/admin/migrate-interests` (around lines 19–27). If `MIGRATION_KEY` is unset, this check is skipped:

```ts
if (expectedKey && migrationKey !== expectedKey) {
  return res.status(401).json({ error: 'Unauthorized: Invalid migration key' })
}
```

Anyone can then set `interests` to `['Open source', 'Systems design', 'Teaching / pedagogy']` on every active node with an empty list. The `catch` returns `err.message`.

Fix:

1. Change the guard to `if (!expectedKey || expectedKey.length < 32 || migrationKey !== expectedKey) return 401`.
2. Use a constant-time compare (`crypto.timingSafeEqual` on equal-length buffers).
3. On failure return `{ error: 'Migration failed' }`. Log the real error server-side only.
4. Rate-limit this path the same way as login (see `src/app.ts`).
5. Set `MIGRATION_KEY` to 32+ random characters in the Render environment. Run the migration once.
6. After a successful run, delete `src/routes/admin.ts`, the import, and `app.use('/api/admin', adminRoutes)` in `src/app.ts`.

Checkbox (do this last, after verification):

- [ ] Migration has been run on production.
- [ ] `src/routes/admin.ts` deleted.
- [ ] `/api/admin` unmounted in `src/app.ts`.
- [ ] `MIGRATION_KEY` removed from Render after deletion.

### `src/routes/upload.ts` — public files and HTML upload

`GET /media/:mediaId` (lines 222–238). With no token, any non-removed file is sent with `res.sendFile`. A private project upload is world-readable if the 24-hex id is known.

`POST /upload` and `POST /upload/archive-evidence` (lines 54–165) take `path.extname(file.originalname)` and the client MIME with no allow-list. A `.html` or unsanitised `.svg` file is stored and served on the same origin as the SPA. A script in that file can read `sessionStorage` and steal the JWT until the cookie migration lands. After the cookie migration, same-origin HTML is still XSS.

`POST /upload/cert-artwork` already allow-lists MIME and sanitises SVG. Copy that discipline.

Fix:

1. Allow-list for general and archive uploads: `image/png`, `image/jpeg`, `image/webp`, `image/gif`, and `application/pdf`. Map those to extensions yourself (`.png`, `.jpg`, `.webp`, `.gif`, `.pdf`). Ignore `file.originalname` for the stored name: `uuid` plus the mapped extension.
2. Reject everything else, including `image/svg+xml` and `text/html`, on these two routes. SVG stays on the certificate route only, and that route must keep calling `sanitiseSvg` before write.
3. `GET /media/:id`: if there is no viewer, serve the file only when the parent project’s visibility is `fully_public` or `process_visible` (reuse `getProjectProcessLogScope`). Otherwise 401. If there is a viewer, apply the same hidden / `hiddenInSpaces` checks that already exist, and also require contributor or space-member access when the project is `space_only`.
4. For PDF, set `Content-Disposition: attachment` and `X-Content-Type-Options: nosniff`. For images, `nosniff` plus the real image content type, not the client-supplied one.
5. Lines 361–364: replace `err.message` with a generic `Failed to process upload`.

### `src/routes/auth.ts` — social recovery takeover

`POST /auth/recover/trustees` (lines 190–257) has no auth, no Zod schema, and no rate limit. The body `alias` is passed to `ChainNode.findOne({ alias })`, so `{"alias":{"$gt":""}}` is a Mongo operator. `newPassword` is hashed with bcrypt before any proof of identity. If trustees later approve (lines 314–323), that hash replaces the account password. `GET /auth/recover/trustees/:requestId` (lines 384–398) returns the whole document, including `newPasswordHash`.

Owner decision: disable these routes.

Fix now:

1. Delete the three handlers: `POST /recover/trustees`, `POST /recover/trustees/:requestId/vote`, `GET /recover/trustees/:requestId`.
2. Leave `RecoveryRequest` and `PUT /nodes/me/trustees` in place.
3. Those paths then 404 through the normal handler. Do not leave a stub that still hashes a password.
4. Register step 4 and the recover page: say trustees can be saved, and recovery through them is not available yet. Remove any copy that says trustees can reset the password today.
5. When this is rebuilt later: require the seed phrase or a logged-in session, Zod-string alias with `^[a-z0-9_-]+$`, password length 8–128, rate limit, notify the account owner with a cancel, show trustees who asked, never return `newPasswordHash`.

### `src/routes/mediations.ts` — unauthenticated dispute records

`GET /mediations/project/:projectId` (lines 527–534) and `GET /mediations/:id` (lines 540–546) have no `requireAuth`. They return parties, proposals, and reasons. `GET /mediations/mine` is correctly behind `requireAuth`.

Fix: add `requireAuth`. Load the mediation’s project and call `assertFullProcessLogReadable`. Also allow the caller if they are `triggeredBy` or in `parties`. Everyone else gets 403. Anonymous gets 401.

## Session cookie (httpOnly)

Do this after media authorization. The JWT in `frontend/src/lib/session.ts` is readable by any injected script.

Backend:

1. Add `cookie-parser`.
2. On register, login, and seed recover, set  
   `Set-Cookie: etch_session=<jwt>; HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=<same as JWT>`.  
   Stop putting `token` in the JSON body. Still return `alias` and, on register only, `seedPhrase`.
3. `Secure` is required in production. In local HTTP dev, omit `Secure` or the cookie will not stick. Gate that on `config.nodeEnv === 'production'`.
4. Add `POST /auth/logout` (clears the cookie) and `GET /auth/me` (returns `{ alias, nodeId }` for the current cookie).
5. `requireAuth` and `optionalAuth` read `req.cookies.etch_session` first. Accept `Authorization: Bearer` only until the frontend is switched, then delete the Bearer branch in the same change if the frontend ships together. Prefer shipping them together.
6. Every non-GET route checks `Origin` (fallback `Sec-Fetch-Site: same-origin`). Reject when `Origin` is present and not in the allow-list. Requests with no `Origin` and `Sec-Fetch-Site: cross-site` are rejected.

CORS in `src/app.ts`:

```ts
cors({
  origin: ['https://whodunnit-etch-app.onrender.com', 'http://localhost:5173', 'http://127.0.0.1:5173'],
  credentials: true,
})
```

Add the Vite port you actually print if it is not 5173. Do not reflect arbitrary origins.

Frontend:

- `api()` uses `credentials: 'include'` and does not set `Authorization`.
- `session.ts` may keep the alias for display. It must not keep the JWT.
- `RequireAuth` calls `GET /auth/me` (cache the result for the session). On failure, redirect to login.
- Sign out calls `POST /auth/logout` then clears the alias and goes to `/`.
- Multipart uploads in `frontend/src/lib/upload.ts` and `TraceForm.tsx` must also send `credentials: 'include'`.

`<img src="/media/:id">` will send the cookie automatically, which is why media auth has to be finished first.

## Medium

### Register race — `src/routes/auth.ts` lines 81–100

Map Mongo `11000` on `alias` to 409 `Alias already taken`. Write the identity block only after `ChainNode.create` succeeds, or delete that block if create fails, so a lost race does not leave a seed ciphertext under the winner’s alias.

### Login case and reserved names

In `loginSchema` and `recoverSchema`, `.trim().toLowerCase()` the alias (Zod transform). Do the same in `LoginPage.tsx` and `RecoverPage.tsx`.

On register, reject `admin`, `system`, `support`, `etch`, `null`, `undefined`, `root`, `moderator` after lowercasing. Return 400 with the same style of message as the regex error.

### Demo reputation — `src/routes/auth.ts` lines 53–71 and 102–114

`DEV_MANDALA_DEMO_SCORES=true` grants high reputation even when `NODE_ENV=production`, as long as `RENDER` is not `true`.

Fix: `shouldSeedDevMandalaDemoScores` returns true only when `config.nodeEnv === 'development'` and the flag is set. Remove the branch that honours the env var in production.

### Seed storage — `src/services/auth.ts`

`hashSeed` is unsalted SHA-256 of the lowercased phrase. A random 12-word phrase is not brute-forceable from that hash. The reversible ciphertext in Mongo is the real risk: database plus `ENCRYPTION_KEY` decrypts every seed.

Do not remove encryption in this pass (recovery and the chain block depend on it). Do compare hashes with `crypto.timingSafeEqual` on equal-length buffers. Document in a code comment that the seed is custodial.

### Unbounded lists and N+1

`src/app.ts` lines 33–36 note that list endpoints return every row. `src/routes/conversations.ts` lines 170–183 run two extra queries per conversation. `GET /notifications` returns the full history, and the bell refetches it every 30 seconds.

Fix for this pass: cap notifications at the latest 50. Cap trace lists at 100 with a `limit` query (default 50, max 100). Leave cursor pagination as a follow-up if those caps are in place. For the conversation list, one aggregation or a single `DmMessage` query grouped by `conversationId` instead of per-row `findOne` + `countDocuments`.

### Open redirect — `frontend/src/lib/session.ts` lines 56–68

`redirectAfterAuth` accepts any `return` that starts with `/` and not `//`. `/\evil.com` normalises to `//evil.com`.

Fix:

```ts
function safeReturnPath(ret: string): string | null {
  if (!ret.startsWith('/') || ret.startsWith('//') || ret.includes('\\') || ret.includes('://')) return null
  const url = new URL(ret, window.location.origin)
  if (url.origin !== window.location.origin) return null
  return url.pathname + url.search + url.hash
}
```

Use that result or fall through to `/dashboard`.

### Certificate SVG — `frontend/src/pages/NftPage.tsx` lines 62–68

`dangerouslySetInnerHTML` renders `artwork.svg`. The server sanitises on write. Keep it. Add a test that `sanitiseSvg` strips `<script>`, `onload`, and `javascript:` URLs. Do not add client-side HTML parsing as a second sanitiser. `style` is in the allow-list in `src/services/svgSanitise.ts`; do not widen that list.

### Suspended users — `src/middleware/optionalAuth.ts` lines 25–28

The query selects `tokenVersion` only. A suspended or removed node with a still-valid token is attached as `req.node`. `requireAuth` already blocks those statuses.

Fix: also select `status`. If status is `suspended` or `removed`, do not set `req.node` (treat as logged out). Do not throw; optional auth should continue anonymous.

### Endorsements and forks

`src/routes/endorsements.ts` `GET /trace/:traceId` and `GET /project/:projectId` (lines 71–84) skip visibility. `src/routes/forks.ts` `GET /parent/:parentProjectId` (lines 106–115) returns every child project.

Fix: endorsements by project call `assertFullProcessLogReadable`. Endorsements by trace load the trace, then the same helper on `trace.projectId`. Forks: call the helper on the parent, then drop child rows whose own project the caller cannot fully read (`getProjectProcessLogScope !== 'full'`).

### Stale hub — `frontend/src/pages/HubPage.tsx` lines 280–341

`load()` writes state. The effect sets `cancel` only after `await load()` returns, so the writes already happened.

Fix: pass a `isCurrent` function into `load` and return before every `setState` when it is false. `SpaceDetailPage.tsx` `load()` has the same hole; use the same pattern there.

### Stale messages — `frontend/src/components/messages/ConversationView.tsx` lines 26–45

`load()` has no generation token. Switching `/messages/:id` lets an older response call `setMessages`. The 5s interval overlaps in-flight loads.

Fix: capture `const requested = conversationId` at the start and ignore the result if `requested` is no longer current. Do not start a poll tick while a load is in flight. Pause the interval when `document.hidden` (see performance).

### Register trustees and interests — `frontend/src/pages/RegisterPage.tsx`

Trustee fields lowercase text and do not apply `^[a-z0-9_-]+$` before submit. Custom interests are only trimmed.

Fix: reject a trustee that fails the alias regex, with the same error string as step 1. Reject a custom interest that is empty after trim, longer than 40 characters, or contains `<` or `>`. The server schema remains the real check.

## Layout and design

Observed on the live site, dark theme only. A later pass screenshots light theme on landing, register, hub, and messages before calling layout done.

- Landing scroll: `Landing.tsx` sets `html, body { overflow: hidden }` and scrolls an inner `.landing-root` with `scroll-snap-type: y mandatory`, `scroll-behavior: smooth`, and every section `height: 100vh`. That fights browser scroll restoration, find-in-page, keyboard scrolling until the container is focused, and the mobile URL bar. On a short or landscape phone, 100vh clips content. Keep snap if the product wants full-screen sections, but use `100dvh`, and make sure the scroller is the document if you drop `overflow: hidden` on `body`. Do not add more scroll-jacking.
- Section “How a trace becomes a record” at 1080p: the diagram sits at the top and the three text columns sit at the bottom with a large empty band. Pull the columns up under the diagram (`justify-content` / less `margin-top: auto`).
- Last section: the footer line (`absolute bottom-6`, `Landing.tsx` around line 728) and the “↑ SCROLL UP” hint (`bottom: 24`) occupy the same spot. Move the hint above the credit, or drop the hint.
- Type and targets: nav and many labels are 9–10 px mono caps. At a 390 px width, EXPLORE and LOGIN are about 14 px tall. Minimum tap size is 24×24 px; 44×44 is the comfortable target. Increase padding on those links and on ENTER THE CHAIN (currently about 35 px tall). Ghost text on near-black is hard to read; use the muted token, not ghost, for any sentence the user must read.
- `document.title` never changes. Set it per route (`Etch — Discover`, `Etch — Register`, and the node alias on a profile).
- Register: `AppShell` renders an `<h1>` from `title="Register"` and the page renders another `<h1>` “CREATE A NODE”. Keep one h1. Alias field label says “3–30 chars” but not “lowercase, digits, _ and -”. Put that in the hint. Set `autoCapitalize="none"`, `autoCorrect="off"`, `spellCheck={false}` on the alias input. Add a confirm-password field and a show/hide toggle. Step 1 says trustees are set “after registration” while step 4 is trustees; after social recovery is disabled, say “You can name trustees in this signup. Using them to recover the account is not available yet.”
- Hero scramble: remove `DecryptedText` on the top label (around lines 306–316) and on “Document what making actually looks like.” (around lines 331–345). ## User-journey errors

- Expired session: `api.ts` has no 401 handling. `RequireAuth` only checks that a token string exists. After 7 days, or after seed recover bumps `tokenVersion`, the UI still looks signed in and every call fails. Fix: on 401, clear the session (or the cookie via logout) and redirect to `/login?reason=expired&return=<current path>`. `LoginPage` already reads `reason` for display; show a one-line “Your session ended. Log in again.”
- Seed loss: register step 1 stores the JWT and puts the seed only in React state. A reload returns to step 1 and the seed is gone. Fix: write the seed to `sessionStorage` under a key like `etch_pending_seed` when step 2 mounts, remove it when the user checks the acknowledgement and continues, and register a `beforeunload` listener while the acknowledgement is unchecked. Do not put the seed in `localStorage`. Do not log it.
- A signed-in user can open `/register` or `/login` and replace their session. If `GET /auth/me` succeeds, redirect those pages to `/dashboard` and show nothing that creates a second account.
- Social recovery UI does not exist. Disabling the routes (Critical) is the fix. Copy on register step 4 and `RecoverPage` must match: seed phrase is the only recovery. Trustees can be saved for later.
- Login, register, and recover finish with `window.location.href`, which re-downloads the shell. After the bundle fix, switch these to `navigate()` from React Router so the JS stays loaded. Keep the safe-return helper.
- Login `Alice` fails today because the server does not lowercase. Unknown alias and bad password show different errors. Both are fixed in the auth section above.
- `/dashboard`, `/me`, and `/nodes/:alias` all render `HubPage`. Canonical path: `/nodes/:alias` for a profile, `/dashboard` redirects to `/nodes/<session alias>`. Keep `/me` as a redirect to the same place so old links work.
- A recovery notification was created with `type: 'collaboration_request'`, so the bell would show it as a collaboration. Those notifications stop when the routes are removed. Do not reuse that type for a future recovery notice; add a dedicated type.
- Cold-start 503 copy and stale hub/space/DM data are covered above.

## Why the app feels slow besides the homepage

- `App.tsx` always mounts `TargetCursor` (`hideDefaultCursor`), `AppAmbientDotField`, `AppAtmosphere`, `MicroChainFlash`, and page transitions. `DotField.tsx` runs a 20 ms interval plus `requestAnimationFrame` (it already skips the loop when `prefers-reduced-motion`).
- `CrystalRadar3D.tsx` runs many `useFrame` hooks on the hub. Pause them when the canvas is off-screen (`IntersectionObserver`) or the tab is hidden.
- Polling with no `document.hidden` pause: `MessagesPage`, `ConversationView`, and `MessagesNavLink` each poll every 5 s (three list polls when messages are open). `SpaceDiscussion` polls every 5 s. `NotificationBell` polls every 30 s and downloads the full list. Pause all of these when `document.hidden`. One list poll is enough; drop the duplicate in `MessagesNavLink` or `MessagesPage`.
- Backend: bcrypt 12 on login is expected (about 200–400 ms). `requireAuth` reads Mongo on every request; leave that, it is the revocation check. Unbounded queries and the conversation N+1 are in Medium. `server.ts` listens before Mongo is ready, so the first calls 503. The waking-up retry covers that. Do not block `listen()` on Mongo; Render needs `/health` early.

## Vibe-coding checklist

Applies here, and is in the findings above:

- Broken object authorization (traces, references, archives, credits, mediations, by-node projects, media, endorsements, forks).
- Open admin route when the key is unset.
- Default JWT secret outside production boot checks.
- Wildcard CORS and CSP disabled.
- Missing rate limits on recover and upload, and on login/register outside production.
- Account enumeration on login and recover.
- Unsanitised upload (HTML/SVG) and stored XSS on the app origin.
- NoSQL operator injection on social recovery (route is being removed).
- Verbose `err.message` on the admin route and certificate upload processing.
- Suspended sessions still treated as logged in on optional-auth routes.
- Stale React state from overlapping fetches.
- Heavy client effects. Reduced motion already gates the dot field; it does not gate the terminal, the cursor, or the radar.

Does not apply: Supabase RLS, Firebase rules, Solidity reentrancy, DEX oracle manipulation, EVM integer overflow, signature replay, MEV. There is no wallet login and no LLM API bill.

Hallucinated npm packages were not found in `package.json`. Dependencies are real packages. Do not add a dependency-confusion cleanup.
